# İki bağımsız repo ile teslim

`designer/` içeriğini, gizli dosyalar dahil, React reposunun köküne kopyalayın. `mcp/` içeriğini Node servis reposunun köküne kopyalayın. İsim veya komşuluk şartı yoktur. İki Git reposu arasında paket yayınlamanız gerekmez. Yerel monorepo içinde entegrasyon testleri için klasör adları designer ve mcp'dir.

1. Kurum tesliminde Designer kurulum rehberindeki SDK, env, tip paketi ve adapter eşlemelerini tamamlayın. Geliştirme sürümünde mevcut vendor paketleri ve lock ile `npm ci` çalışır.
2. Designer repo kökünde `npm run build` frontend çıktısını üretir. CI için proje kökünde `piri-settings.json` ve `.azure-pipelines/` YAML'larını kurum değerleriyle doldurun. Şablonlardaki tüm çift alt çizgili değerler eşlenmeli. Her namespace için envSpecific bölümünü tekrarlayın. INT/UAT/PREP scriptleri frontend örneğindeki bağımsız uygulama bayraklarını kullanır. Kurumun ortak Docker şablonunun çağırdığı CLI ve build parametrelerini kendi kurulumunuzda eşleyin. WebSocket anahtarı, SDK tarafından JS bundle'a aktarılan ve kurum init betiği tarafından desteklenen gerçek anahtar olmalı. Değeri `wss://<MCP Route host>/ws`, routes[0].host ise Designer hostudur. İlk kabul için route path `/`. Ortak Azure repo tanımında örnekteki bağımsız shell / microfrontend=false frontend ayarlarını isteyin. Ortak şablon ile gelen init.sh ve deploy/ dosyalarını deployment CLI yönetir.
3. Designer repo kökünde `npm run export:mcp -- /tam/yol/mcp-reposu` çalıştırın. Üretilen `generated/` değişikliklerini MCP reposunda inceleyip commit edin. Export yalnız adı ui-designer-mcp olan hedef projeyi kabul eder. Yeni build tamamlandığında eski recipe'lerin yerini yeni set alır.
4. MCP repo kökünde kendi README'sine göre `npm ci && npm run build` çalıştırın. O Docker image yalnız MCP repo içeriğinden üretilir. Her iki projenin pipeline ve release'ini kendi standardıyla çalıştırın.
5. INT ortamında Designer'ı HTTPS ile açın. Tarayıcıdaki WSS hedefi gerçek ortamı göstermeli. IDE'den MCP kataloğu ile kurum bileşenini sorgulayın, validate ve import çağrılarından sonra get_design ile aynı revizyonu okuyun. Yalnız /health kontrolü bu bağı doğrulamaz.

Kurum referansından görülen sözleşme şablonlara işlendi. Gerçek registry, Azure pipeline kaydı, DNS, TLS, OpenShift, Chromium ve IDE kabulü kurum ortamında yapılır.
